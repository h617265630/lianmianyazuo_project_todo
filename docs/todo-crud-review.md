# Todo、用户与项目关联检查

## 关联规则

- `todos.user_id` 必填，关联一个用户。删除用户时，其 Todo 会随之删除。
- `todos.project_id` 可空：一条 Todo 可独立存在，或关联一个项目；一个项目可关联多条 Todo。
- 解除项目关联使用 `PATCH /api/todos/:id` 和 `{ "projectId": null }`。不传该字段表示保持原值。
- 项目外键配置 `ON DELETE SET NULL`：数据库删除项目时，Todo 保留并变为未关联。但当前应用没有项目删除入口或接口。
- `parent_id` 支持父子 Todo，删除父 Todo 会级联删除子 Todo；提醒、附件记录、评论、任务关联与看板关联也有级联外键。
- 当前访问模型是用户归属：私有 Todo 查询、修改、删除只允许所属用户，关联项目也必须属于该用户。项目成员/团队表尚未接入这套 Todo 权限。
- 首页和全部待办页读取公开的 open/done 接口，可展示不同用户的 Todo；显示不代表有修改权限。

## 已知边界

- 项目自身 CRUD 尚不完整：有创建、列表、详情、状态/阶段/进度修改；没有项目删除、名称/描述修改。
- 首页公开创建允许选择 n/v，属于原有协作行为；公开读取和创建接口未改为私有接口。它与“只有所属账号能修改/删除”的模型并不等同于完整团队协作权限。
- 当前“今日待办”按创建日期筛选；“本周待办”按手动 horizon 筛选，不是按截止日期自动归类。
- 父子任务有数据库级联；本次核心 CRUD 验证针对独立 Todo 和项目关联，不覆盖深层父子关系、循环检测或整个团队权限系统。

## 验证

- `npm run typecheck`：前后端类型检查。
- `npm run build`：前端生产构建。
- `node tests/todo-crud.mjs`：本地开发 API 回归；使用种子账号，只创建带唯一标记的临时 Todo，并在 finally 中清理。
- 回归覆盖：独立/关联创建、读取、关联/解除、状态/日期更新、空标题/无效状态/无效项目、跨账号修改删除拦截、删除后的数据库查询。

## 界面与备用样式

- 工作台统一为暖白底、墨绿色强调色；调整导航、项目入口、统计、历史侧栏和资料预览，收紧项目/待办页的布局。
- 顶部“待办样式”提供“原版 / 备用版”。默认原版；备用版增加优先级侧边标记和信息分隔。仅切换展示，共用同一套 CRUD 逻辑。
- 样式偏好保存在本机浏览器，刷新后保持；保留浅色/深色切换。
- 修复项目进度条填充宽度为零，以及手机资料区溢出。
