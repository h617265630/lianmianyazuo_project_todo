08 · 如何阅读这个项目 —— 给新人的 4 周入门路径

回答：我应该先读哪一份代码，按什么顺序读，读的时候盯着什么看？

0. 这是一篇师兄视角的导读

我在仓库里挖了一圈以后，给你画一张心智地图。它有五层，每层只关心自己的事：

层关心的对象在仓库里的入口
L0 · 物理与仿真MJCF / MuJoCo / BAMsrc/mjlab_microduck/robot/microduck/*.xml
L1 · 环境env_cfg / mdp 函数 / DRsrc/mjlab_microduck/tasks/*.py
L2 · 训练PPO / rsl_rl / runner间接：mjlab 包，触发点在 train_cli.py
L3 · 导出与发布ONNX / manifest / Hubsrc/mjlab_microduck/export.py、publish/
L4 · 真机daemon / robotd / updater不在这个仓库！在 pollen-robotics/microduck

1. 整体代码地图（按依赖关系分层）

Layer 0 · 物理与仿真（先有身体，再有脑子）

  • MJCF 模型 — robot_walk.xml / robot_groundcontact.xml
  • Scene — scene.xml / scene_walk.xml / scene_rollers.xml
  • BAM 物理 — src/mjlab_microduck/actuator/friction_dr_bam.py
  • 关键常量 — src/mjlab_microduck/robot/microduck_constants.py

Layer 1 · 环境（env / mdp）

  • 任务注册表 — tasks/__init__.py
  • 入口 cfg — microduck_velocity_env_cfg.py
  • MDP 函数库 — src/mjlab_microduck/tasks/mdp.py（7188 行、230 个函数）
  • Backlash 变体 — src/mjlab_microduck/tasks/backlash.py

Layer 2 · 训练（PPO / rsl_rl）

训练算法本身（PPO、rsl_rl）在 mjlab 包里，不重写。MicroduckOnPolicyRunner 只覆写一行 — 把 symmetry cfg 里的 _env 引用剔掉再 dump yaml。

Layer 3 · 导出与发布（ONNX / manifest）

  • 导出 — src/mjlab_microduck/export.py（311 行）
  • Manifest — src/mjlab_microduck/publish/manifest.py（386 行，没有 mjlab / torch import）

2. 推荐 4 周阅读计划（每天 1-2 小时）

Week 1 · 把 MuJoCo 那层吃透

  • Day 1-2：MuJoCo + scene.xml，装 MuJoCo viewer，打开 scene.xml
  • Day 3-4：robot_walk.xml 与 14 DOF，通读 default 段
  • Day 5-7：BAM actuator，通读 friction_dr_bam.py

Week 2 · 把 env / mdp 这层读通

  • Day 1-3：microduck_constants.HOME_FRAME
  • Day 4-5：mdp.py 主要函数（_fallen_mask、upright_progress）
  • Day 6-7：microduck_velocity_env_cfg.py

Week 3 · 训练、导出、发布

  • Day 1-3：rsl_rl 训练流程，MicroduckOnPolicyRunner
  • Day 4-5：export.py
  • Day 6-7：publish/manifest.py

Week 4 · 真机回路 + 综合实战

  • Day 1-3：infer_policy.py 调试策略
  • Day 4-5：pollen-robotics/microduck 真机 daemon
  • Day 6-7：综合实战——小改一个 cfg + 训 5 iter

8. 写在最后

microduck_rl 仓库最有意思的不是某一段代码，而是它每个角落都有一句注释解释"为什么这里不能这样写"。这些注释不是写给 review 的，是写给"六个月后回来改的自己"的。

读这个仓库最有效的姿势，不是逐行读，是带着问题读：
  • "为什么这个 reward weight 是这个数？"
  • "为什么这个正则要 ^(?!passive_)？"
  • "为什么这里要 monkey-patch mjlab 的 compute_returns？"
每个问题背后都有一次具体的失败。AGENTS.md 是这些故事的目录；git log 是故事本身；代码是结局。
