# 03 · 让鸭子更像活物 —— 从"执行命令"到"有生命感"

> 一个能走 / 能踢 / 能坐的机器**依然是机械的**。让它"像活物"，是另一层
> 设计——不在 RL 内部，而在**行为的编排层 + 闲置动作 + 反应触发**。

---

## 1. 什么叫"像活物"

对比两个场景：

| 不像活物 | 像活物 |
|---|---|
| 给指令才动，不给指令就僵住 | 不给指令时晃头、踱步、梳理羽毛 |
| 100% 重复同一动作 | 走路时偶尔绊一下、停一下看 |
| 一接命令立刻响应 | 假装"思考"一下再执行 |
| 永远成功执行 | 偶尔失败——踢偏、没站稳 |
| 表情（LED）恒定 | 收到指令时亮眼、摔倒了低头 |

Pollen Robotics 在产品页提到了：

> "a per-robot generated voice"（每台机器人独有的合成声音）

这暗示：**音频反馈是个体性的**，不是统一播报。

---

## 2. 行为分层的思路

把鸭子的行为想成 **3 层金字塔**：

```
          ▲
         /│\         第 3 层：性格 / 个性（idle 动作、声音、LED 节奏）
        / │ \            ↑ 长期不变，但每次执行有微小差异
       /──┼──\
      /  │  \        第 2 层：反应 / 触发（被吓到 → 颤一下）
     /   │   \          ↑ 由事件驱动：声音、触摸、NFC、视觉
    /────┼────\
   / 技能层  \        第 1 层：技能 / 任务（走、踢、鞠躬）
  /─────────────\       ↑ 当前 ONNX 策略
```

**当前仓库已经在第 1 层很扎实**；第 2 层主要由 daemon 和外层应用负责；
第 3 层基本是空白——这是你**最值得发挥**的层。

---

## 3. 闲置动作（idle behavior）

鸭子不动的时候干嘛？**决不能僵直**。几种思路：

### 3.1 头部 idle
- 当前已经有 `head_pose(4)` 在 13D 命令块里，**散步时让 head 微微晃**
- 训一个 head_idle 策略，或者直接写一个 head 摆动函数 + sinusoidal 命令

### 3.2 踱步
- 走路指令加微小的随机扰动，让速度不是 0
- 用 `lin_vel_x ∈ {0, 0.05, -0.05}` 微随机采样

### 3.3 姿态整理
- 偶尔触发一个 0.5 s 的"伸懒腰" episodic 策略
- 触发概率按时间累计：闲置越久 → 越可能触发

> 这些都不需要重新训大策略，**只需要在 daemon 加个 idle 调度器**。

---

## 4. 反应层（reactive layer）

机器人"被吓到"是最经典的活物感来源。**真机上有现成的传感器**可以用：

| 传感器 | 触发 | 反应 |
|---|---|---|
| IMU（自由落体加速度） | 检测到自由落体 | 缩颈、亮眼（摔倒反射） |
| ToF（深度） | 突然有东西靠近 | 抬头看 |
| 麦克风 | 突然响声 | 头转向声源 |
| 触摸（鸟喙夹爪） | 被触碰 | 抓住、摆动 |
| NFC | 读到 NFC 标签 | 触发对应 episodic |

鸭子**自带 IMU + ToF + 麦克风 + NFC + 摄像头**，**传感器在等待被利用**。

> 当前任务里：IMU 用于状态估计，ToF 还没怎么用，麦克风/摄像头基本没动。

---

## 5. "个性"——如何训练

最经济的"个性"做法：**给每个动作加随机种子 + 噪声**。

### 5.1 物理层随机
```python
# 每个 episode 重新采样
friction = rng.uniform(0.7, 1.3)
voltage  = rng.uniform(6.5, 8.2)
# → 同一动作看起来不一样（步幅、节奏）
```

这在训练里已经有，叫**域随机化**。但 daemon 上线后**没有继续随机化**
—— 这是一个工程 gap：让发布出去的 ONNX 在真机上每次也带点随机。

### 5.2 行为层随机
- 走路速度指令加 ±5% 噪声
- head idle 加正弦扰动（不同 phase = 不同个性）
- 不同个体（不同机器人）训不同模型

### 5.3 高级：fine-tune per-robot
- 出厂训一个通用 walk.onnx
- 每台鸭子到用户手里后，用**用户的 1 小时数据** fine-tune 几轮
- 结果：每台鸭子步态略微不同 → 个性

## 6. LED 表达（被忽视的维度）

仓库 `assets/speaker.part` 存在，但 LED 模型不在这个仓库里——LED 是
硬件 + daemon 控制的，**不在 RL 训练栈范围**。

鸭子 LED 可以表达：

| 状态 | 颜色 / 节奏 |
|---|---|
| 待机 | 呼吸蓝 |
| 行走 | 稳态白 |
| 摔倒 | 红色闪烁 |
| 收到指令 | 绿色脉冲 |
| 困惑 | 黄色慢闪 |
| 高兴 | 彩虹渐变 |

**这是让鸭子有"表情"最便宜的一招**，duck 头顶 + 眼睛（如果有 LED）一起
做就能立竿见影。

---

## 7. 声音 / 语音

鸭子有麦克风 + 扬声器 + 合成语音。常见的"活物感"声音设计：

- **音效代替状态**：摔倒 → "嘎"，鞠躬 → "嘎嘎"，停止 → 安静
- **指令反馈**：听到"过来" → "嘎！"（确认） → 走过来
- **咕哝声**：闲置时偶尔发一声非常短的"嘎？"
- **无意义音节**：让 duck 偶尔像在自言自语

> **不要做"语音助手"**——鸭子是动物感，不是智能音箱。
> 一个"嘎"比"好的，我来走"更可爱。

---

## 8. 总结：让鸭子"活"的 5 个具体动作

按 ROI（投入产出比）排序：

| 优先级 | 改动 | 效果 |
|---|---|---|
| 🥇 1 | LED 颜色映射状态 | 一眼能看出来是活的 |
| 🥈 2 | 闲置时 head 微动 + 偶尔踱步 | 不会僵 |
| 🥉 3 | 摔倒音效 + 挣扎几下再躺 | "失败"也是表达 |
| 4 | 触碰 / 声音触发反应 | 互动感 |
| 5 | 多策略混合编排 + 个体微调 | 个性 |

前 3 项**不需要重新训 RL**，纯靠 daemon 编排层就能做出来——这正是
`duck_分析/` 这个项目可以尝试的方向。
