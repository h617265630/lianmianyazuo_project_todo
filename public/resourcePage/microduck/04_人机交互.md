# 04 · 人机交互 —— 怎么"指挥"一只鸭子

> 鸭子从硬件上提供了 5 种交互通道：游戏手柄、NFC、语音、LED、动作触发。
> 这一篇把每种通道从硬件到 daemon API 到应用层串起来。

---

## 2. 游戏手柄（padd）

鸭子出厂带一只游戏手柄（参考 marketing materials）。

| 按键 | 功能（推测，参考仓库 manifest + 7 个 slot） |
|---|---|
| 左摇杆 | 速度指令（vx, vy）→ walk slot |
| 右摇杆 | 旋转 + 头部 yaw/pitch |
| A / B / X / Y | 触发 episodic：sitstand / ground_pick / kick_left / kick_right |
| RB / LB | 切换 walk ↔ stand |
| 方向键 + R3 | 触发 roulade |
| Select | 切策略预设 |

**协议层**：
- 手柄 → BLE / USB → `padd` daemon
- `padd` 把按键转成 robotd 内部事件
- robotd 把事件分发到：
  - 当前 perpetual slot 的 cmd 输入（vx/vy/w）
  - 触发 episodic（`robot do <skill>`）

> **怎么训一个"听话的鸭子"**：把游戏手柄的指令映射到 obs 的 `twist(3)` 部分，
> 然后训 `Mjlab-Velocity-Flat-MicroDuck`。**训出来的策略本来就能响应手柄**。

## 3. NFC

鸭子**头上 + 鸟喙各有一个 NFC 天线**（硬件规格确认）。

| 用法 | 场景 |
|---|---|
| NFC 标签 = 触发器 | 把标签贴到杯子边上 → 鸭子靠近时自动 grab |
| 拍头触发 | 用户拍鸭子头 → NFC 读到手机 → 触发鞠躬 |
| Dev Pack 10 个标签 | 训练用：每个标签对应一个动作 |

**daemon 的 NFC 处理**：
- `nfcd`（推测存在）轮询 NFC 天线
- 读到 UID → 查表 → 触发 `robot do <对应技能>`
- 标签也可以带"参数"（比如不同 UID = 不同速度）

> 这是**给非技术用户最友好的交互方式**：把鸭子带到一个标签边上，它就动了。

## 4. 语音

鸭子有**麦克风 + 扬声器**，但仓库里没看到语音识别模块（不在 RL 训练栈范围）。

**当前推测的能力**（基于产品页 + 一般机器人设计）：

| 能力 | 实现 |
|---|---|
| 听到声音方向 | 麦克风阵列 DOA（如果多 mic） |
| 唤醒词 | 本地 wakeword（小词表，节能） |
| 短指令 ASR | 云端 / 本地 Whisper-tiny |
| 反馈语音 | 预录"嘎"音效 / 合成语音 |
| 自主发声 | 闲置时发出"嘎？" |

**注意**：从产品描述 "per-robot generated voice" 来看，**每台鸭子声音不同**，
所以是 TTS 生成而不是预录音频——这给"个性"留了空间。

## 5. LED 视觉反馈

LED 不只是装饰，**是机器人状态的可视化协议**。

| 模式 | 含义 | 用户感知 |
|---|---|---|
| 慢呼吸 | 待机 / 健康 | 安心 |
| 持续常亮 | 正在执行 | "它在忙" |
| 闪烁 | 警报 / 错误 | 提示 |
| 颜色 | 不同语义 | 不需要记文档也能看懂 |

LED 控制大概率在 `robotd` 内部，**应用层通过 protobuf IPC** 设置模式。
RL 训练栈不直接控制 LED——解耦干净。

## 6. 动作触发（最原生的方式）

有时候**不需要任何传感器**，直接：

```bash
# CLI / Python 脚本
robotctl robot do bow
```

应用场景：
- **WebRTC 远程控制**：网页按钮 → 后端 → `robotctl`
- **BLE 手机 app**：app 按钮 → BLE → daemon → 执行
- **MQTT / ROS 集成**：上层框架调度

## 7. 一次完整的"交互剧本"

**场景**：用户拍了一下鸭子的头，鸭子歪头打量，然后鞠躬。

```
1. 用户拍头
   └─▶ NFC 天线读到手机 UID
       └─▶ nfcd 查表：UID 1234 = "pet"
           └─▶ robotd 收到事件 "pet"
               └─▶ 调度：head_idle (episodic, 0.8s)
                   └─▶ duck 歪头 + LED 闪一下
2. head_idle 结束
   └─▶ daemon 自动回到 walk slot（idle twist）
3. 1.5s 后
   └─▶ 调度：bow (episodic, 3s)
       └─▶ duck 鞠躬 + 喇叭播放"嘎"
       └─▶ 期间 LED 慢闪绿
4. bow 结束
   └─▶ 回到 walk idle
```

整个流程里 **RL 网络只做了"具体动作的执行"**，**调度、状态、感知都在 daemon**。

## 8. 你能从这里学到的"机器人交互设计原则"

1. **多通道冗余**：同一个意图用多种方式都能触发（手柄 / NFC / 语音 / 触摸）
2. **状态可见**：LED / 声音让用户知道"它在干嘛"
3. **永远可中断**：用户随时按停 → 机器人能安全停下
4. **失败可读**：摔倒 = 红色 LED + 挣扎动作，不是黑屏
5. **每条交互都有反馈**：哪怕只是"嘎"一声，别静默
6. **不要装作很聪明**：听不懂就"歪头"，不要假装懂

## 9. 你能立刻做的事

1. **试游戏手柄**：`padd` daemon 起来 → 按按钮 → 看 `journalctl -u robotd`
2. **试 NFC**：把任意 NFC 标签放到鸭子头上 → 看 daemon 日志
3. **试 LED**：通过 `robotctl led set --color blue --pattern breathe`（推测 API）
4. **写一个调度脚本**：用 Python 调用 `robotctl` 编排一段小剧本

第 4 步是上手最快的——它让你**实际感受到"互动"的逻辑**是怎么拼起来的。
