🦆 duck_分析 — Microduck 项目学习笔记本

README · 项目介绍
这是一个边做边学的目录：你每学到一个点就追加一条笔记（notes/），每跑通一个实验就贴一张图或一段日志（figures/）。不需要写得很整齐，先记下来比写得好更重要。

Microduck 是 Pollen Robotics / Hugging Face 推出的一台 25 cm 高、约 800 g 的开源双足机器人，全身 14 个 Dynamixel XL330 智能伺服。本仓库 microduck_rl/ 是它的官方 RL 训练栈（mjlab + MuJoCo Warp + PPO），真机运行时在 pollen-robotics/microduck。

这台鸭子到底是什么 —— 一句话总结

一台会感知（IMU + 摄像头 + ToF + 触觉）、会思考（ONNX 策略网络 50 Hz）、会执行（14 个位置伺服 + 一个能"抓"的鸟喙）的双足机器人，全部跑在一个 RK3566（4×A55）上，整机含电池 800 g，续航约 1 小时，零售价 $399。

01 · 训练入门 —— 把鸭子跑起来

目标：搞清楚训练一次策略到底在干嘛，以及 14 个伺服怎么从权重变成动作。

1. 最小观看流程（不训练）

# 假设你已经有 out.onnx（怎么来见第 3 节）
uv run scripts/infer_policy.py --walking out.onnx

│             │ obs[61]                                              │

关键命令

# 列出所有可用任务
uv run list-envs

# 烟雾测试：64 env × 5 iter，10 分钟能跑完
uv run train Mjlab-Velocity-Flat-MicroDuck \

    --agent.max_iterations 5

# 正式训练（需要 GPU）

    --env.scene.num-envs 4096

3. "任务"到底是什么

仓库里 src/mjlab_microduck/tasks/ 每个 microduck_*.py 都是一个任务（env 配置）。

任务 ID干什么
Mjlab-Velocity-Flat-MicroDuck速度指令跟踪（走路，最基础）
Mjlab-Velocity-Rough-MicroDuck同上，地形是起伏的
Mjlab-VelStand-Flat-MicroDuck速度 + 站立组合（VelStand）
Mjlab-StandUp-Flat-MicroDuck摔倒后站起来（episodic）
Mjlab-SitStand-Flat-MicroDuck坐 ↔ 立切换（双向，受命令控制）
Mjlab-GroundPick-Flat-MicroDuck用鸟喙"捡"东西
Mjlab-BallKick-Flat-MicroDuck踢球
Mjlab-Roulade-Flat-MicroDuck前滚翻（最花哨的一个）

4. RL 新手极简术语表

术语一句话在鸭子里的具体含义
环境 (env)仿真的世界4096 份 MuJoCo，每份放一只鸭子
状态 (state)世界的全部信息MuJoCo 内部的 qpos + qvel
观测 (obs)鸭子能"看到"的信息61 维向量：关节角 + IMU + 速度指令
动作 (action)鸭子能"做"的事14 维：每个伺服的目标角度偏移
策略 (policy)obs → action 的映射一个 MLP，~几十 KB
奖励 (reward)这一步"做得好不好"走路快 + 摔倒 - 抖动 -
PPO 更新用一批数据让策略"变好"一次反向传播 + 梯度裁剪
episode从头到尾的一次尝试鸭子从站立 → 摔倒 / 走完
iteration收集一批数据 + 更新一次24 步 × 4096 env ≈ 100k transition

02 · 多动作联合训练 —— 怎么让鸭子会很多事

核心答案：每个动作是一个独立的 ONNX 策略，运行时由 daemon 按 slot 切换。

官方动作 / 槽位表

SLOTS = ("walk", "stand", "sitstand", "ground_pick",
         "kick_left", "kick_right", "roulade")
Slot含义任务 IDkind
walk走路（默认）Mjlab-Velocity-Flat-MicroDuckperpetual
stand站立（专用的站立任务）perpetual
sitstand坐 ↔ 站（按命令切换）Mjlab-SitStand-Flat-MicroDuckperpetual
ground_pick用嘴捡东西Mjlab-GroundPick-Flat-MicroDuckepisodic
kick_left左脚踢球Mjlab-BallKick-Flat-MicroDuckepisodic
kick_right右脚踢球Mjlab-BallKick-Flat-MicroDuckepisodic
roulade前滚翻Mjlab-Roulade-Flat-MicroDuckepisodic

kind 字段：episodic vs perpetual

  • perpetual（永久性的）：没有终止时间，一直跑直到 daemon 让它停。走路 / 站立 / sitstand 都是这种。
  • episodic（一次性的）：有时间限制 duration_s，到时间自己停。踢球 / 滚翻 / 捡东西都是这种。

多个 ONNX 在运行时是怎么"联合"起来的

鸭子不是"一个大脑"，而是"一窝专家 + 一个调度员"。

┌─────────────────────────────────────────────────────────────┐
│  robotd (Rust daemon, 50 Hz)                                  │
│  ┌──────────┐    policy_id    ┌──────────────────────────┐   │
│  │ Scheduler │ ──────────────▶ │ 当前激活的 ONNX 推理     │   │
│  │ (state    │                 │ (单线程 onnxruntime)    │   │
│  │  machine) │ ◀──────────────  │                         │   │
│  └──────────┘    ctrl[14]     └──────────────────────────┘   │
│       ▲                                  ▲                   │
│       │ gamepad / NFC / voice / app      │ obs[61]           │
└───────┼──────────────────────────────────┼───────────────────┘

自己加一个新动作的完整流程

# 1. 写任务配置（加到 tasks/）
# 2. 在 tasks/__init__.py 注册
# 3. 训练
uv run train Mjlab-Bow-Flat-MicroDuck --env.scene.num-envs 4096

# 4. 发布
uv run publish --task Mjlab-Bow-Flat-MicroDuck \
    --wandb-run-path <...> \
    --repo /microduck-bow \
    --kind episodic --duration-s 3.0

# 5. 真机加载
sudo robotctl policy add bow /microduck-bow
robotctl robot do bow   # 触发鞠躬

03 · 让鸭子更像活物 —— 从"执行命令"到"有生命感"

一个能走 / 能踢 / 能坐的机器依然是机械的。让它"像活物"，是另一层设计。

什么叫"像活物"

不像活物像活物
给指令才动，不给指令就僵住不给指令时晃头、踱步、梳理羽毛
100% 重复同一动作走路时偶尔绊一下、停一下看
一接命令立刻响应假装"思考"一下再执行
永远成功执行偶尔失败——踢偏、没站稳
表情（LED）恒定收到指令时亮眼、摔倒了低头

行为分层的思路

          ▲
         /│\         第 3 层：性格 / 个性（idle 动作、声音、LED 节奏）
        / │ \            ↑ 长期不变，但每次执行有微小差异
       /──┼──\
      /  │  \        第 2 层：反应 / 触发（被吓到 → 颤一下）
     /   │   \          ↑ 由事件驱动：声音、触摸、NFC、视觉
    /────┼────\
   / 技能层  \        第 1 层：技能 / 任务（走、踢、鞠躬）
  /─────────────\       ↑ 当前 ONNX 策略

闲置动作（idle behavior）

  • 头部 idle：散步时让 head 微微晃，训一个 head_idle 策略或 sinusoidal 命令
  • 踱步：走路指令加微小的随机扰动，让速度不是 0
  • 姿态整理：偶尔触发一个 0.5 s 的"伸懒腰" episodic 策略

让鸭子"活"的 5 个具体动作（按 ROI 排序）

优先级改动效果
🥇 1LED 颜色映射状态一眼能看出来是活的
🥈 2闲置时 head 微动 + 偶尔踱步不会僵
🥉 3摔倒音效 + 挣扎几下再躺"失败"也是表达
4触碰 / 声音触发反应互动感
5多策略混合编排 + 个体微调个性

04 · 人机交互 —— 怎么"指挥"一只鸭子

鸭子从硬件上提供了 5 种交互通道：游戏手柄、NFC、语音、LED、动作触发。

5 种交互通道总览

                 ┌─────────────────────────────────────────────┐
                 │            duck（RK3566）                      │
                 │   🎮 gamepad  ────▶ robotd / padd            │
                 │   🏷️  NFC      ────▶ robotd / nfc             │
                 │   🎤 mic       ────▶ wakeword + ASR          │
                 │   💡 LED       ◀──── robotd                   │
                 │   🔊 speaker   ◀──── robotd                   │
                 └────────────┬─────────────────────────────────┘
                              │ WebRTC / WiFi
                              ▼
                 ┌────────────────────────────────────────────┐
                 │   App / CLI                                  │
                 │   - robotctl policy add / do                 │
                 │   - WebRTC video                             │
                 └────────────────────────────────────────────┘

游戏手柄（padd）

按键功能（推测）
左摇杆速度指令（vx, vy）→ walk slot
右摇杆旋转 + 头部 yaw/pitch
A / B / X / Y触发 episodic：sitstand / ground_pick / kick_left / kick_right
RB / LB切换 walk ↔ stand

交互设计原则

  1. 多通道冗余：同一个意图用多种方式都能触发（手柄 / NFC / 语音 / 触摸）
  2. 状态可见：LED / 声音让用户知道"它在干嘛"
  3. 永远可中断：用户随时按停 → 机器人能安全停下
  4. 失败可读：摔倒 = 红色 LED + 挣扎动作，不是黑屏
  5. 每条交互都有反馈：哪怕只是"嘎"一声，别静默

07 · 打通软硬件 + RL 的任督二脉

核心论点：通过 Microduck 这一个真实项目，把"硬件 + 软件 + 强化学习"三层从抽象名词变成可改的代码行。

为什么"打通"很难 —— 三类典型困境

困境典型表现仓库里的破局点
纯软件 → 不会硬件调一周 reward，仿真走稳，到真机跌倒friction_dr_bam.py 把电压-电流-摩擦显式建模
纯硬件 → 不会 RL能 PWM 控制 SG90，但不知策略怎么训microduck_velocity_env_cfg.py 把 task 用 dataclass 拆开
纯 RL → 不会落地HalfCheetah 训得不错，但 ONNX 怎么上板没碰过export.py + publish/cli.py 把 train → ONNX → HF Hub → robotctl load 画成 4 条命令

7 步打通路线

  1. 步 1：会用 MuJoCo viewer（Week 1–2）：打开 scene.xml；infer_policy.py 按 WASD/IJKL
  2. 步 2：改一个 reward（Week 3–4）：改 pose.weight 1.0 → 1.5，跑 5-iter smoke
  3. 步 3：加一个新传感器（Week 5–6）：加 ContactSensorCfg 监测 foot contact
  4. 步 4：用真实伺服校准 BAM（Week 7–8）：跑 validate_bam_testbench.py
  5. 步 5：训一个简单任务（Week 9–10）：5-iter smoke → 4096 env 跑 1000 iter
  6. 步 6：部署到真机（Week 11–12）：export.py → publish → robotctl policy load
  7. 步 7：端到端调通（Week 13–16）：发现真机会向后倒 → 检查 IMU 偏置

30 / 90 / 180 天计划

时间窗目标具体任务
Day 1–30把鸭子跑起来 + 改通 reward步 1+2+3
Day 31–90端到端跑通 1 个任务步 4+5 + 1000 iter
Day 91–180真机闭环（哪怕是替代品）步 6+7 + wiki 总结

08 · 如何阅读这个项目 —— 给新人的 4 周入门路径

回答：我应该先读哪一份代码，按什么顺序读，读的时候盯着什么看？

整体代码地图（按依赖关系分层）

层关心的对象在仓库里的入口

  • Week 2：把 env / mdp 这层读通（HOME_FRAME、mdp.py 主要函数、velocity_env_cfg）

Microduck 在生态中的位置

Microduck 是"RL + 腿足 + 端到端"路径上能买到的最低门槛实物。
  • 比它便宜的：仿真（MuJoCo / Isaac Lab，$0）；桌面臂 SO-ARM100（无腿，$100）
  • 比它便宜的腿足实物：几乎没有 —— Stanford Pupper 自购件可压到 $600，但属于四足 DIY 路线
  • 同价位唯一对手：Reachy Mini（$299/$449）但它是无腿桌面头 + 对话路线

推荐学习组合（按路径）

  • 路径 A：全栈通用路线：Microduck（$399）→ Unitree G1（$13.5k+）→ Reachy 2 / Unitree H1
  • 路径 B：操作专项路线：SO-ARM100 + LeRobot（$200）→ ALOHA / Mobile ALOHA（$20k–32k）→ Franka Panda
  • 路径 C：学术控制路线：Microduck（$399）→ Open Dynamic Robot Initiative Solo（$15k–30k）→ MIT Mini Cheetah

选购注意事项

  1. 价格 ≠ 能力：Trossen WidowX AI $4.5k 在 LeRobot 上比某些 $15k 桌面臂更易用
  2. 开源 ≠ 免费：硬件 CAD 全开源，但 BOM / 训练数据 / 部署栈仍要付费
  3. 控制频率是分水岭：500 Hz 以下桌面级跑 RL 微调很容易；1 kHz 力矩环以上才适合高动态接触任务
  4. sim2real 不等于"训练一次就行"：Microduck 同价位优势在于训练栈与硬件一体
