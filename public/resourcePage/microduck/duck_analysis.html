README — 项目介绍

Microduck 是 Pollen Robotics / Hugging Face 推出的一台 25 cm 高、约 800 g 的开源双足机器人，全身 14 个 Dynamixel XL330 智能伺服。本仓库 microduck_rl/ 是它的官方 RL 训练栈（mjlab + MuJoCo Warp + PPO），真机运行时在 pollen-robotics/microduck。

一台会感知（IMU + 摄像头 + ToF + 触觉）、会思考（ONNX 策略网络 50 Hz）、会执行（14 个位置伺服 + 一个能"抓"的鸟喙）的双足机器人，全部跑在一个 RK3566（4×A55）上，整机含电池 800 g，续航约 1 小时，零售价 $399。

01

训练入门 — 把鸭子跑起来

目标：搞清楚训练一次策略到底在干嘛，以及14个伺服怎么从权重变成动作。

最小观看流程（不训练）

# 假设你已经有 out.onnx（怎么来见第3节）
uv run scripts/infer_policy.py --walking out.onnx

会弹出一个Python写的MuJoCo viewer，鸭子按策略运行（按WASD/IJKL控制前进/转向/头部位姿）。

一次完整训练在做什么

MuJoCo Warp (mjlab) · 4096个并行机器人

物理仿真50Hz → 14个XL330 BAM电机模型 → 接触+摩擦

obs[61] → PPO策略网络 → wandb记录reward/loss/视频

每一秒：obs→action→step→reward→PPO更新

关键命令

# 列出所有可用任务
uv run list-envs

# 烟雾测试：64 env × 5 iter，10分钟能跑完
uv run train Mjlab-Velocity-Flat-MicroDuck \
    --env.scene.num-envs 64 --agent.max_iterations 5

# 正式训练（需要GPU）
uv run train Mjlab-Velocity-Flat-MicroDuck --env.scene.num-envs 4096

"任务"到底是什么

仓库里每个microduck_*.py都是一个任务（env配置）。任务 = 机器人 + 场景 + 观测 + 奖励 + 终止条件 + 域随机化的组合。

任务ID功能
Mjlab-Velocity-Flat-MicroDuck速度指令跟踪（走路，最基础）
Mjlab-Velocity-Rough-MicroDuck同上，地形是起伏的
Mjlab-StandUp-Flat-MicroDuck摔倒后站起来
Mjlab-SitStand-Flat-MicroDuck坐↔立切换
Mjlab-BallKick-Flat-MicroDuck踢球
Mjlab-Roulade-Flat-MicroDuck前滚翻
02

多动作联合训练 — 让鸭子会很多事

每个动作是一个独立的ONNX策略，运行时由daemon按slot切换。这不是"一个网络搞定一切"，而是"多个专家，编排层做调度"。

官方动作/槽位表

SLOTS = ("walk", "stand", "sitstand", "ground_pick", "kick_left", "kick_right", "roulade")
Slot含义类型
walk走路（默认）perpetual
stand站立perpetual
sitstand坐↔站perpetual
ground_pick用嘴捡东西episodic
kick_left/right踢球episodic
roulade前滚翻episodic

perpetual = 永久性的，无终止时间；episodic = 一次性的，有duration_s限制

运行时联合原理

robotd (Rust daemon, 50 Hz)

Scheduler → 当前激活的ONNX推理（单线程onnxruntime）

同时只跑一个ONNX，切换是瞬时的，不是blend

观测是61D共享的，切换由daemon决定

04

人机交互 — 怎么"指挥"一只鸭子

5种交互通道总览

🎮gamepad → robotd/padd
🏷️NFC → robotd/nfc
🎤mic → wakeword + ASR
💡LED ← robotd
🔊speaker ← robotd

游戏手柄按键（推测）

按键功能
左摇杆速度指令（vx, vy）→ walk slot
右摇杆旋转 + 头部 yaw/pitch
A/B/X/Y触发episodic
RB/LB切换walk↔stand
方向键+R3触发roulade

机器人交互设计原则

  1. 多通道冗余：同一意图用多种方式都能触发
  2. 状态可见：LED/声音让用户知道"它在干嘛"
  3. 永远可中断：用户随时按停能安全停下
  4. 失败可读：摔倒 = 红色LED + 挣扎动作
  5. 每条交互都有反馈：哪怕只是"嘎"一声
  6. 不要装作很聪明：听不懂就"歪头"

打通软硬件与RL的任督二脉

面向已经能跑smoke test、但卡在"知道这代码在干嘛、不知为什么这么写"的同学。核心论点：通过Microduck这一个真实项目，把"硬件+软件+强化学习"三层从抽象名词变成可改的代码行。

三层交集点

交集触点文件一句话解释
硬件→RLactuator/friction_dr_bam.py:37-47BAM把电压→电机力矩→摩擦预算封装成RL可见的扭矩
硬件→RLrobot/microduck_constants.py:132-145vin_range把NP-F550电池电压波动烤成DR
软件→RLmicroduck_velocity_env_cfg.py:193-340env cfg把task用dataclass拆开
RL→硬件src/export.py:252-267normalizer烤进ONNX = actor(normalizer(obs))

7步打通路线

步1 MuJoCo viewer（Week 1-2）
步2 改一个reward（Week 3-4）
步3 加一个新传感器（Week 5-6）
步4 校准BAM（Week 7-8）
步5 训一个简单任务（Week 9-10）
步6 部署到真机（Week 11-12）
步7 端到端调通（Week 13-16）
