01 · 训练入门 —— 把鸭子跑起来

目标：搞清楚训练一次策略到底在干嘛，以及 14 个伺服怎么从权重变成动作。

1. 最小观看流程（不训练）

最快能看到"会动的鸭子"：

# 假设你已经有 out.onnx（怎么来见第 3 节）
uv run scripts/infer_policy.py --walking out.onnx

会弹出一个 Python 写的 MuJoCo viewer，鸭子按策略运行（按 WASD/IJKL 控制前进 / 转向 / 头部位姿）。这是离策略演示，不是训练，但能让你直观看到"权重 → 动作 → 关节 → 摔倒 / 走路"的链路。

2. 一次完整训练在做什么

2.1 RL 框架图

┌────────────────────────────────────────────────────────────────────┐
│   MuJoCo Warp (mjlab)              4096 个并行机器人（4096 个 env）│
│   ┌──────────────────┐  ctrl[14]  ┌──────────────┐                │
│   │  物理仿真 50Hz    │ ──────────▶│ 14 个 XL330  │                │
│   │  + 接触 + 摩擦    │            │ BAM 电机模型 │                │
│   └──────────────────┘  状态/传感 │ + 域随机化    │                │
│             ▲                    └──────────────┘                │
│             │ obs[61]                                              │
│   ┌──────────────────┐                                             │
│   │  PPO 策略网络     │ ◀── wandb 记录 reward / loss / 视频       │
│   └──────────────────┘                                             │
└────────────────────────────────────────────────────────────────────┘

每一秒钟发生的事情：

  1. obs = build_observation(env) —— 当前姿态、关节角、IMU、目标速度等拼成 61 维向量
  2. action = policy(obs) —— 一个 MLP（一般是 [256, 256, 128] 之类）输出 14 维动作
  3. env.step(action) —— 把 14 维当"目标关节角"，由 BAM 物理模型转成真实力矩
  4. reward = compute_reward(...) —— 算奖励（走得快 +、摔倒 -、能耗 -、抖动 -）
  5. 收集一批 transition（24 步 × 4096 env）后做 PPO 更新一次
  6. 重复 4000–6000 次（"iterations"），大概 1–2 小时

2.2 关键命令

# 列出所有可用任务
uv run list-envs

# 烟雾测试：64 env × 5 iter，10 分钟能跑完
uv run train Mjlab-Velocity-Flat-MicroDuck \
    --env.scene.num-envs 64 \
    --agent.max_iterations 5

# 正式训练（需要 GPU）
uv run train Mjlab-Velocity-Flat-MicroDuck \
    --env.scene.num-envs 4096

# 训练完看效果
uv run play Mjlab-Velocity-Flat-MicroDuck --wandb-run-path

2.3 训出来的权重怎么上机器人

# 1) 把 checkpoint 导出成 ONNX（normalizer 烧进去，必须走这条路）
uv run scripts/export.py Mjlab-Velocity-Flat-MicroDuck \
    --wandb-run-path 

# 2) 发布到 Hugging Face Hub
uv run publish --task Mjlab-Velocity-Flat-MicroDuck \
    --wandb-run-path  \
    --repo /microduck-my-walk \
    --kind perpetual --slot walk

# 3) 在真机上加载
sudo robotctl policy load walk /microduck-my-walk

3. "任务"到底是什么

仓库里 src/mjlab_microduck/tasks/ 每个 microduck_*.py 都是一个任务（env 配置）。任务 = 机器人 + 场景 + 观测 + 奖励 + 终止条件 + 域随机化的一个组合。

任务 ID干什么
Mjlab-Velocity-Flat-MicroDuck速度指令跟踪（走路，最基础）
Mjlab-Velocity-Rough-MicroDuck同上，地形是起伏的
Mjlab-VelStand-Flat-MicroDuck速度 + 站立组合（VelStand）
Mjlab-StandUp-Flat-MicroDuck摔倒后站起来（episodic）
Mjlab-SitStand-Flat-MicroDuck坐 ↔ 立切换（双向，受命令控制）
Mjlab-GroundPick-Flat-MicroDuck用鸟喙"捡"东西
Mjlab-BallKick-Flat-MicroDuck踢球
Mjlab-Roulade-Flat-MicroDuck前滚翻（最花哨的一个）

4. RL 新手极简术语表

术语一句话在鸭子里的具体含义
环境 (env)仿真的世界4096 份 MuJoCo，每份放一只鸭子
状态 (state)世界的全部信息MuJoCo 内部的 qpos + qvel
观测 (obs)鸭子能"看到"的信息61 维向量：关节角 + IMU + 速度指令
动作 (action)鸭子能"做"的事14 维：每个伺服的目标角度偏移
策略 (policy)obs → action 的映射一个 MLP，~几十 KB
奖励 (reward)这一步"做得好不好"走路快 + 摔倒 - 抖动 -
回报 (return)一整个 episode 的累积奖励~5000 步里加起来的 reward
优势 (advantage)这一步比平均好多少PPO 用来更新策略的关键量
PPO 更新用一批数据让策略"变好"一次反向传播 + 梯度裁剪
episode从头到尾的一次尝试鸭子从站立 → 摔倒 / 走完
iteration收集一批数据 + 更新一次24 步 × 4096 env ≈ 100k transition
checkpoint训练中的存档model_2999.pt 这种
sim2real仿真训出来的能用在真机上见 AGENTS.md 那一堆 invariant

5. 看训练日志该看什么

wandb 项目名是 mjlab_microduck。判断训练是不是在进步，看这些：

Episode_Reward/track_lin_vel_xy      ← 主要正向：跟速度指令越准越好
Episode_Reward/lin_vel_z             ← 应该 ≤ 0（往上跳会被罚）
Episode_Reward/action_rate           ← 应该 ≤ 0，抖动惩罚
Episode_Reward/base_height           ← 应该 ≤ 0，倒地惩罚
Mean episode_length                  ← 应该上升，摔倒频率下降
AGENTS.md 里有句箴言必须记住： 每一个 Episode_Reward/<penalty> 在 wandb 里都应该是 ≤ 0。 如果你看到任何 penalty 变成正的，意味着奖励设计被策略"利用"了。

6. 推荐起点

第一次训练：

# 烟雾测试（必跑，10 分钟）
uv run train Mjlab-Velocity-Flat-MicroDuck \
    --env.scene.num-envs 64 --agent.max_iterations 5

# 正式训 walking（看 PPO 跑 4000 iter 大概要 2 小时 on RTX 4090）
uv run train Mjlab-Velocity-Flat-MicroDuck \
    --env.scene.num-envs 4096

然后 uv run play 看效果，如果只是"会晃但不走"：

  • 训练时长还不够，再训 1000 iter
  • 看 lin_vel_z 是不是被政策利用（往上跳）
  • 看 Mean episode_length 是不是稳定上升
