04 · 人机交互 —— 怎么"指挥"一只鸭子

鸭子从硬件上提供了 5 种交互通道：游戏手柄、NFC、语音、LED、动作触发。

1. 5 种交互通道总览

                 ┌─────────────────────────────────────────────┐
                 │            duck（RK3566）                      │
                 │   🎮 gamepad  ────▶ robotd / padd            │
                 │   🏷️  NFC      ────▶ robotd / nfc             │
                 │   🎤 mic       ────▶ wakeword + ASR          │
                 │   💡 LED       ◀──── robotd                   │
                 │   🔊 speaker   ◀──── robotd                   │
                 └────────────┬─────────────────────────────────┘
                              │ WebRTC / WiFi
                              ▼
                 ┌────────────────────────────────────────────┐
                 │   App / CLI                                  │
                 │   - robotctl policy add / do                 │
                 │   - WebRTC video                             │
                 └────────────────────────────────────────────┘

2. 游戏手柄（padd）

按键功能（推测）
左摇杆速度指令（vx, vy）→ walk slot
右摇杆旋转 + 头部 yaw/pitch
A / B / X / Y触发 episodic：sitstand / ground_pick / kick_left / kick_right
RB / LB切换 walk ↔ stand
方向键 + R3触发 roulade

3. NFC

鸭子头上 + 鸟喙各有一个 NFC 天线。

用法场景
NFC 标签 = 触发器把标签贴到杯子边上 → 鸭子靠近时自动 grab
拍头触发用户拍鸭子头 → NFC 读到手机 → 触发鞠躬
Dev Pack 10 个标签训练用：每个标签对应一个动作
这是给非技术用户最友好的交互方式：把鸭子带到一个标签边上，它就动了。

4. 语音

鸭子有麦克风 + 扬声器，但仓库里没看到语音识别模块。

能力实现
听到声音方向麦克风阵列 DOA（如果多 mic）
唤醒词本地 wakeword（小词表，节能）
短指令 ASR云端 / 本地 Whisper-tiny
反馈语音预录"嘎"音效 / 合成语音

5. LED 视觉反馈

LED 不只是装饰，是机器人状态的可视化协议。

模式含义用户感知
慢呼吸待机 / 健康安心
持续常亮正在执行"它在忙"
闪烁警报 / 错误提示
颜色不同语义不需要记文档也能看懂

7. 一次完整的"交互剧本"

场景：用户拍了一下鸭子的头，鸭子歪头打量，然后鞠躬。

1. 用户拍头
   └─▶ NFC 天线读到手机 UID
       └─▶ nfcd 查表：UID 1234 = "pet"
           └─▶ robotd 收到事件 "pet"
               └─▶ 调度：head_idle (episodic, 0.8s)
                   └─▶ duck 歪头 + LED 闪一下
2. head_idle 结束
   └─▶ daemon 自动回到 walk slot（idle twist）
3. 1.5s 后
   └─▶ 调度：bow (episodic, 3s)
       └─▶ duck 鞠躬 + 喇叭播放"嘎"
       └─▶ 期间 LED 慢闪绿
4. bow 结束
   └─▶ 回到 walk idle

整个流程里 RL 网络只做了"具体动作的执行"，调度、状态、感知都在 daemon。

8. 你能从这里学到的"机器人交互设计原则"

  1. 多通道冗余：同一个意图用多种方式都能触发（手柄 / NFC / 语音 / 触摸）
  2. 状态可见：LED / 声音让用户知道"它在干嘛"
  3. 永远可中断：用户随时按停 → 机器人能安全停下
  4. 失败可读：摔倒 = 红色 LED + 挣扎动作，不是黑屏
  5. 每条交互都有反馈：哪怕只是"嘎"一声，别静默
  6. 不要装作很聪明：听不懂就"歪头"，不要假装懂
