# 从零造一台自己的机器人——一份"创业指南"式的工程化路径

> 本文面向想从仿真走到真机的工程师 / 研究员 / 学生。读完你应该能选好第一台硬件、在两周内跑通仿真 smoke test，并知道未来 6–12 个月每一阶段要买什么、做什么、踩哪些坑。
>
> 范式参照：microduck_rl 项目——一个 800 g、25 cm、14 个 Dynamixel XL330 的双足机器人，仿真训策略、ONNX 导出、Jetson 真机部署。这套路径是本文主轴。

---

## 0. 总原则

**从轮子到腿、从仿真到真机、从开箱到自研**——这三条路径同时推进。

| 原则 | 解释 | 为什么 |
|------|------|--------|
| 先仿真，再半实物，最后真机 | 第一版策略必须在 sim 里跑出能看的录像 | 仿真失败 0 元，真机失败 200 元+受伤风险 |
| 从轮式到腿式 | 差速驱动底盘 + 简单 RL → 桌面腿式 → 自研双足 | 失败半径递增，先把 RL/部署链路打通 |
| 复用现成 BOM | Stanford Pupper / SO-ARM100 / Solo12 BOM 全公开 | 自研 = 集成，不是从零画 PCB |
| 训推同栈 | 训练用 mjlab + PPO，部署用 ONNX Runtime | 不同栈必崩（normalizer / 帧率 / 观测顺序） |
| 视频 + 指标双验证 | wandb 指标 + 真实录像 + 末端状态聚类 | 指标可骗，眼睛不会 |

## 1. 阶段 0：纯仿真（$0，1–2 周）

**目标**：把 RL 链路跑通——能训一个在仿真里"会走"的策略，不碰任何硬件。

### 1.1 工具栈

| 组件 | 选型 | 理由 |
|------|------|------|
| 仿真器 | MuJoCo Warp（`mujoco-warp` 0.3.x）+ mjlab 1.3+ | 速度比 CPU MuJoCo 快 50–200×，mjlab 是 RL-first 框架 |
| 训练 | rsl_rl 的 PPO | 双足 / 四足社区事实标准 |
| 部署格式 | ONNX（normalizer 内嵌） | Jetson / RK3566 全栈通用 |
| Python | 3.11 | mjlab 不支持 3.12 |
| 硬件 | 单卡 4090 / 4080，4096 envs | 4096 envs 是双足 PPO 的"甜点" |

### 1.2 项目

直接 clone microduck_rl：

```bash
git clone https://github.com/pollen-robotics/microduck_rl
cd microduck_rl
uv sync
uv run list-envs
```

看到 `Microduck-Velocity-Flat-...` / `-Rough-...` / `-Backlash-...` 系列即说明 OK。

### 1.3 第一个任务：smoke test

```bash
# 5 个 iteration、64 个 env，2 分钟跑完——能提前暴露 95% 的配置错误
uv run train Microduck-Velocity-Flat \
   --env.scene.num-envs 64 \
   --agent.max_iterations 5
```

通过条件：
- 没有 NaN / CUDA OOM
- obs 维度 = 61（48 base + 13 command block）
- 每个 reward term 都有非零梯度
- ONNX 导出成功

### 1.4 产出

- 一个能"小碎步走 0.5 m/s"的 PPO checkpoint
- 一个 ONNX 文件，包含 baked-in normalizer
- 跑通的 `play` + `infer_policy.py` 链路

> 这是你后面所有阶段的"母版"——仿真→真机的接口契约（obs 维度、归一化、动作范围、控制频率）从今天就锁死。

### 2.2 第一个任务：巡线 + 避障（JetBot 推荐）

```python
# JetBot collision-avoidance pseudocode
import torch, torchvision
model = torch.load('collision_net.pt').cuda().eval()
camera = CSI_Camera()  # IMX219 160° FOV

while True:
    img = camera.read()              # 224×224 RGB
    steer = model(img).item()        # -1.0 .. +1.0
    robot.left_motor.value =  0.3 + 0.2 * steer
    robot.right_motor.value = 0.3 - 0.2 * steer
```

ROS2 集成（TurtleBot 3 Burger）：

```bash
sudo apt install ros-humble-turtlebot3*

ros2 launch turtlebot3_bringup robot.launch.py
ros2 launch turtlebot3_cartographer cartographer.launch.py
```

### 2.3 RL 在这里怎么用

- **导航策略**：在 Gazebo 里训 `TurtleBot3-Velocity-Flat`，迁移到真机（摩擦 DR 是必修课）
- **避障策略**：在 Isaac Sim / Webots 里训，离策略蒸馏到 ONNX

### 2.4 仿真→真机链路

Gazebo + ROS2 → ONNX → `rclpy` 节点调用 ONNX Runtime → `/cmd_vel` topic。

### 3.3 第一个 RL 任务：reach

```python
# LeRobot SO-ARM100 reach policy
from lerobot.common.policies.act.modeling_act import ACTPolicy
import torch

policy = ACTPolicy.from_pretrained("user/reach-policy")
obs = {"observation.state": robot.get_joint_state()}  # 7-DOF
action = policy.select_action(obs)                    # 7-DOF delta
robot.command(action.cpu().numpy())
```

`mjlab` / `robosuite` / `maniskill` 里都有 SO-ARM100 / Panda 的对应模型——可以直接拿 Panda 模型训 SO-ARM100（关节顺序不同，要 remap）。

### 3.4 仿真→真机要点

- **力矩饱和**：仿真里的电机是 ideal torque，真机 STS3215 有 stall torque = 30 kg·cm 上限
- **齿轮间隙**：SO-ARM100 的 3D 打印齿轮有 ~3° backlash，仿真里要加 backlash 模型
- **通信延迟**：USB2TTL → Feetech 协议，每帧 ~5–10 ms，要做 action chunk

### 4.4 仿真→真机链路

| 仿真组件 | 真机对应 |
|----------|----------|
| MJCF 刚体 | 3D 打印件 + 舵机 |
| `dof_pos` / `dof_vel` | 编码器读数 |
| IMU sensor | MPU6050 / ICM-42688-P |
| `dof_frictionloss` DR | 舵机 voltage drop（要测） |
| PD controller (XML) | PCA9685 PWM → MG996R（无编码器反馈 → 闭环差） |

> **注意**：MG996R 是 PWM 控制舵机，没有外部编码器反馈，跟 microduck 的 Dynamixel 完全不同。两种选择：(1) 把策略训成"位置命令 → 角度"模式，让 MG996R 内环 PID 兜底；(2) 换 LX-16A 或 XL330 全总线舵机。

### 5.2 PCB 设计（KiCad 入门）

#### 5.2.1 必备模块

1. **主控最小系统**：STM32F4 (F405 / F411) 或 ESP32-S3
   - 8 MHz 晶振 + LDO 3.3V + SWD 调试口 + USB-C + 启动 / 复位按键
2. **伺服驱动总线接口**：
   - TTL half-duplex：MAX485 + 1 个方向控制 GPIO（XL330 / XC330）
   - PWM：直接 GPIO + PCA9685（MG996R / LX-16A）
3. **IMU 接口**：SPI 或 I2C，4.7 kΩ 上拉
4. **电源管理**：MP2307 / TPS5430 DCDC + 输入防反 + TVS
5. **CAN / RS485 收发器**（可选，4S 电池或大尺寸机器人）
6. **电池电压监测**：分压电阻 → ADC（防过放）
7. **IMU 隔离**：把 IMU 放在 PCB 软垫 / 弹簧上，microduck 的实测教训——PCB 弯曲会让 IMU 偏几十度

#### 5.2.2 入门教程

- KiCad 官方 Getting Started: https://docs.kicad.org
- STM32 KiCad 模板: https://github.com/musicbobd/KiCad-STM32-Template
- microduck 团队推荐的 PCB 工程师社区: EEVblog / Chris Gammell 的 Contextual Electronics

### 5.3 机械设计

- **Onshape**（免费教育版）：microduck 团队用，参数化建模 + 直接生成 MJCF（onshape-to-robot）
- **Fusion 360**：个人版免费，仿真 / CAM 集成好
- **FreeCAD**：开源，但 STL 导出质量参差

设计 checklist：
- 关键尺寸 ±0.1 mm，公差标注
- 装配顺序：每一步都能徒手拆装（不要"先装 A，再装 B，最后发现 C 拆不下来"）
- 走线槽：缆线穿过但不暴露
- 重心：双足站立时 CoM 落在髋中心 ±5 mm

### 5.4 软件

#### 5.4.1 上位机（micro_rl 移植）

```python
# /opt/micro_rl/runtime/policy_runner.py
import onnxruntime as ort
import numpy as np

class PolicyRunner:
    def __init__(self, onnx_path: str):
        self.sess = ort.InferenceSession(onnx_path, providers=['CUDAExecutionProvider', 'CPUExecutionProvider'])
        self.obs = np.zeros(61, dtype=np.float32)

    def step(self, qpos, qvel, imu, last_action):
        self.obs[:48] = np.concatenate([qpos, qvel, imu, last_action])
        # command block 13D 由 daemon 写入（保持 0 表示 stand）
        action = self.sess.run(None, {'obs': self.obs[None, :]})[0][0]
        return np.clip(action, -1.0, 1.0)
```

#### 5.4.2 下位机（STM32 / ESP32 固件）

Dynamixel 协议 2.0 + IMU 读取 + 50 Hz control loop：

```c
// 伪代码：50 Hz 主循环
while (1) {
    uint32_t t0 = micros();
    dynamixel_sync_read_positions(joint_ids, 14, qpos);
    bmi270_read(imu);
    if (micros() - t0 < 8000) {  // 8 ms 留给上位机
        send_obs_uart(imu, qpos);
        wait_action_uart(action);
    }
    dynamixel_sync_write_positions(joint_ids, action);
    while (micros() - t0 < 20000) __WFI();  // 补足 20 ms
}
```

#### 5.4.3 通信：ROS2 / Zenoh / 自定义

| 协议 | 延迟 | 适用场景 |
|------|------|----------|
| UART 921600 | ~2 ms | 单机，最简单 |
| USB2TTL + Feetech | ~5 ms | SO-ARM100 |

### 5.5 仿真→真机：执行器建模

microduck 用 **BAM 模型**（电压控制 + 摩擦估计）。自己造可以选择：

| 模型 | 复杂度 | 何时用 |
|------|--------|--------|
| PD controller (XML) | ★☆☆ | 入门，PWM 舵机 |
| Position/Velocity control (Dynamixel) | ★★☆ | XL330 / XL430 |
| **BAM 电压模型** | ★★★ | microduck 同款，研究级 |
| 电机 + 减速器 + 摩擦 6 参数 | ★★★★ | 论文级，仿真→真机差距最小 |

## 9. 常见失败模式 + 对策

| 失败模式 | 症状 | 对策 |
|----------|------|------|
| **硬件到不了仿真精度** | 仿真走得好，真机摔跤 | DR 必须覆盖质量 / 摩擦 / 延迟 / 间隙；microduck 的 backlash 模型就是为此而设 |
| **训练时长不够** | 跑了 200 iter 没收敛就放弃 | 简单 episodic ≈ 1000 iter；gaits / 课程学习 ≈ 4000–6000 iter |
| **通信延迟失控** | 50 Hz 控制却用了 30 ms ROS2 | 仿真里直接训 latency-DR；真机走 UART + 共享内存 |
| **电池续航不足** | 5 分钟就掉链 | 先测满载电流（用万用表测），再算 `mAh / 平均电流 × 0.7（安全系数）` |
| **散热不够** | Jetson Orin 烫到 throttle | 加散热片 + 风扇；thermal throttle 是隐形的，watchdog |
| **IMU 噪声爆炸** | 站立抖动 | IMU 软垫 + BMI270 / ICM-42688（不要用 MPU6050） |
| **关节打滑** | 编码器读数和实际不同步 | 电流饱和检测 + IMU 角速度校验 |
| **3D 打印件断** | PLA 太脆 | 换 PETG / ABS；关键受力件加 50% 填充 + 4 周 |
| **ONNX 不一致** | 仿真精度 OK，ONNX 跑偏 | normalizer 必须 baked-in（`scripts/export.py`），不要手动转换 |
| **sim2real gap 反复修不好** | 加 DR 就崩 | 一次只加一种 DR，watch 录像找原因；microduck 的 AGENTS.md 把这写成铁律 |

## 10. 写在最后

从仿真到出货，没有"加速键"。microduck 团队花了一年从 mjlab 的模板训出第一条能走的策略，再花半年处理 sim2real 的每一道墙。这条路是通的，但每一步都要求"先仿真、再半实物、再真机"，"从轮式到腿式"，"复用现成 BOM，集成而非重造"。

读到这里，你应该知道：
- 阶段 0 跑通 microduck_rl smoke test（1–2 周，$0）
- 阶段 1 选一台轮式底盘（JetBot / TurtleBot 3），把 sim→real 链路打通
- 阶段 2 用 SO-ARM100 训 pick-and-place
- 阶段 3 训一条腿足策略（microduck 训栈 + Pupper 硬件）
- 阶段 4 自研 BOM，PCB + 机械 + 固件 + 训练栈移植
- 阶段 5 出货

**下一步**：克隆 microduck_rl，跑 `uv run train Microduck-Velocity-Flat --env.scene.num-envs 64 --agent.max_iterations 5`。看到"Episode_Reward"在 wandb 里爬升时，就该去买第一台硬件了。
